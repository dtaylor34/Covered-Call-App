Setup

Getting started

1
Open the APIs tab
Scroll the tab bar to find the 🔌 APIs tab. You'll see the broker hub with Charles Schwab available and other brokers listed as coming soon.
2
Click "Connect" on Charles Schwab
The Schwab setup flow opens. You'll see the step-by-step guide and the exact callback URL to paste into the Schwab Developer Portal.
3
Create a Schwab Developer account
Go to developer.schwab.com — separate from your brokerage login. Register an app, select both API products, paste the callback URL exactly as shown.
4
Wait for Schwab approval (2–5 business days)
Schwab reviews all developer app registrations. Status shows "Approved — Pending" initially. You'll get an email when approved.
5
Paste your App Key and App Secret into the app
Copy both from your approved Schwab Developer app. These are stored encrypted in Firestore — never exposed to the browser or logged.
6
Complete the OAuth flow
A Schwab login window opens. Sign in with your regular brokerage credentials and select which accounts to authorize. The app handles the rest.
7
Select your default account
After OAuth, the app shows all linked accounts with masked numbers. Pick your default — you can switch any time.
8
Live data starts flowing
The status dot in the APIs tab turns green. Real-time quotes, positions, and option chains are now active across the app.
Security

Callback URL & PII — broker-by-broker guide

Every broker connection involves a callback URL and an authentication handshake. This section explains exactly what each broker sees, what our app stores, and how to configure your developer app to minimize data exposure.

🛡
The golden rule: The callback URL is a one-time receiver for an authorization code — it never contains your personal data. Our app validates and discards the code immediately. It is never logged, stored, or reused.
SCH
Charles Schwab
OAuth 2.0 · developer.schwab.com
Phase 1 — Live ›
Callback URL format
https://[your-domain].web.app/api/schwab/callback
No PII in this URL. Schwab appends ?code=…&state=… — the code is a one-time token (expires in ~30 sec). The state param is a random nonce the app generates to prevent CSRF. Both are consumed server-side and never persisted.
✅ What Schwab receives
Your Schwab login email when you sign in (their own system)
Your app name from the Developer Portal (you choose this)
The callback URL you registered (no personal data)
Which accounts you authorize during the OAuth screen
🚫 What Schwab does NOT receive
Any data from our app
Your email address from our Firebase Auth
Any analytics or usage data from our app
🗄 What our app stores (Firestore, per-user, encrypted)
App Key + App Secret — encrypted at rest in your user document
Access token — 30-min lifetime, auto-refreshed by Cloud Function
Refresh token — 7-day lifetime, rotated on each refresh
Account hash values — Schwab's obfuscated IDs, not real account numbers
Never stored: your Schwab password, full account numbers, SSN, or login email

Security checklist for your Developer Portal setup

✓
Use HTTPS — Schwab requires HTTPS for all production callbacks. localhost is only valid for local dev.
✓
No PII in the path — The callback URL must not contain your email, name, or user ID. Correct: /api/schwab/callback. Wrong: /callback/john@email.com.
✓
Copy-paste the URL exactly — Schwab's OAuth rejects any redirect that doesn't precisely match the registered URL. Don't retype it.
✓
App Type: Individual Use — This limits the OAuth grant to only your account. Prevents broader permission scope requests.
✓
State parameter — Our app generates a random nonce as the state param and validates it on return. This prevents CSRF token injection attacks.
!
Don't share your App Secret — It's the equivalent of a password. Anyone with your App Key + App Secret can impersonate your developer app.
ET
E*TRADE
OAuth 1.0a · developer.etrade.com
Phase 2 — Coming soon ›
⚠
OAuth 1.0a is more complex than OAuth 2.0. It uses signed requests rather than bearer tokens — your credentials are never sent in a URL, but the setup has more steps.
Callback URL format
https://[your-domain].web.app/api/etrade/callback
E*TRADE supports both a registered callback URL and out-of-band (oob) mode where users receive a PIN to paste. We use the registered URL to keep the flow seamless. The URL receives a ?oauth_token=…&oauth_verifier=… — neither contains PII.
✅ What E*TRADE receives
Your E*TRADE login credentials during OAuth (their own system)
Signed request tokens with HMAC-SHA1 signatures (no raw credentials in transit)
Your registered callback URL (no personal data)
🗄 What our app stores
Consumer Key + Consumer Secret — encrypted in Firestore
OAuth access token + token secret — no expiry by default, revocable by user
Never stored: your E*TRADE password or account numbers

Security checklist

✓
HTTPS required — E*TRADE rejects HTTP callbacks in production.
✓
No PII in path — Callback URL must be a clean path. The oauth_verifier appended is a short-lived token, not personal data.
✓
Signed requests — All OAuth 1.0a calls are HMAC-SHA1 signed server-side. Your Consumer Secret never appears in a URL or browser request.
!
Tokens don't expire automatically — E*TRADE OAuth tokens are long-lived. Users should revoke access in their E*TRADE account if they disconnect from our app.
!
Consumer Secret = high value target — Guard it like a password. Unlike OAuth 2.0, there is no short-lived refresh cycle.

Tastytrade
Session auth · api.tastyworks.com
Phase 2 — Coming soon ›
⚠
No OAuth — session-based auth. Tastytrade does not use OAuth. Users authenticate with username + password, which our backend exchanges for a session token. We never store or log the username or password. The credential exchange happens exclusively in the Cloud Function.
Callback URL
N/A — no OAuth redirect flow
Tastytrade uses a direct credential exchange. There is no callback URL to configure, so there is no risk of PII leaking through a redirect chain. The risk profile is different — see the security checklist below.
✅ What Tastytrade receives
Your Tastytrade username + password — sent over HTTPS to their auth endpoint only
Session token requests — standard API calls, no personal data in URLs
🗄 What our app stores
Session token only — encrypted in Firestore, not the credentials
Never stored: your Tastytrade username, password, or account numbers

Security checklist

✓
Credentials handled server-side only — Username and password flow through Cloud Functions and are never accessible from browser code.
✓
HTTPS only — All requests to Tastytrade's API use TLS. The session token in transit is never exposed.
!
Session tokens expire — Typically every 24 hours. The app will prompt re-authentication when the session lapses.
!
No refresh token model — Unlike OAuth 2.0, there's no refresh cycle. Re-auth requires the user to enter credentials again through the secure in-app form.
✗
Do not reuse passwords — Because credentials are submitted for session exchange (even server-side), use a unique Tastytrade password not shared with other accounts.

Accounts

Switching between accounts

Most users have multiple accounts — Individual, Roth IRA, Traditional IRA. The app lets you connect all of them in one OAuth flow and switch without reconnecting.

How account switching works

  • During the OAuth flow, Schwab shows all accounts in your brokerage. You authorize access to all of them at once.
  • The APIs tab shows all linked accounts with masked numbers (e.g. ····1234 ····5678).
  • Tap any account to make it the default. The selection persists across sessions.
  • Switching accounts re-fetches positions and buying power. Quotes and option chains are account-independent — they switch instantly.
ℹ
The app only reads account data — positions, balances. It does not place trades. Order entry is not part of Phase 1.
Authentication

Token lifecycle & reconnecting

Schwab uses a two-token system. Tokens are managed automatically — you only see a prompt when the refresh token itself expires.

TokenLifetimeWhat happens on expiry
Access token30 minutesAuto-refreshed silently by Cloud Function before each API call
Refresh token7 daysApp prompts you to re-run the OAuth flow (one click)
⚠
If you don't open the app for 7+ days, you'll need to re-authorize. This is Schwab's security policy — it ensures stale tokens can't be used indefinitely.

Troubleshooting

OAuth fails with "redirect_uri mismatch"

The callback URL in your Schwab Developer Portal doesn't exactly match what the app sends. Copy-paste the URL from the APIs tab — don't retype it. Check for trailing slashes or http:// vs https://.

Status shows "Approved — Pending"

Schwab's app is still under review. This typically takes 2–5 business days. You'll receive an email when approved. The app will show a waiting state in the APIs tab.

Positions not updating

Positions are fetched on session start. Pull-to-refresh in the APIs tab to force a re-fetch. If positions are stale, your refresh token may have expired — reconnect via the APIs tab.

Quotes show "—" after connection

Schwab's Market Data API may be unavailable outside trading hours for some products. Check the status dot — if it's amber, the session is connected but the market data endpoint returned an error.

App prompts to reconnect after a week

This is expected. Schwab's refresh token has a 7-day lifetime. Click "Reconnect" in the APIs tab to re-run the OAuth flow — it takes about 30 seconds.

Multiple accounts not showing

During the OAuth screen, Schwab lists all accounts in your brokerage. Ensure you ticked all accounts before approving. If you missed one, you'll need to disconnect and re-run the OAuth flow.

FAQ

Frequently asked questions

Can the app place trades on my behalf?

No. Phase 1 is read-only — positions, balances, quotes, and option chains. Order placement is planned for Phase 3 and will require explicit opt-in with a confirmation screen.

Where are my App Key and App Secret stored?

Encrypted in Firestore under your user document. They are never stored in the browser, in local storage, or in the app bundle. Access is restricted to your authenticated Firebase session.

Can the app see my full account number?

No. Schwab returns obfuscated hash values, not real account numbers. The app displays only the last 4 digits for identification (e.g. ····1234). Full account numbers are never transmitted to our systems.

What happens if I revoke access in Schwab?

All tokens are immediately invalidated. The app will show a disconnected state on the next API call. You can reconnect at any time from the APIs tab.

Is this different from Plaid or account aggregators?

Yes. This is a direct integration with Schwab's official developer API, not a screen-scraper. It uses Schwab's own OAuth and provides live market data (quotes, option chains) that aggregators don't offer.

Can I connect multiple brokers at once?

Multi-broker simultaneous connection is planned for Phase 3. In Phase 1, one broker connection is active at a time.

Does the app work after market hours?

Position and account data is always available. Live quotes and option chains require market hours for real-time data — outside those hours the app shows the most recent close price with an "as of close" label.

How do I disconnect a broker?

From the APIs tab, tap the connected broker and select "Disconnect." This deletes all stored tokens from Firestore and revokes the session. Also revoke access from your Schwab Developer Portal for a full cleanup.
